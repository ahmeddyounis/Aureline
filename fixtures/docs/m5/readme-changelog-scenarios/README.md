# README / Changelog Maintenance Scenarios

These fixtures are valid, export-safe `release_docs_maintenance_surface_record`
packets that exercise the branch/release/channel scope, the local-versus-shared
evidence scope, the reopenable compare history, the publish/export boundary, and
the in-product integration anchors that release-facing docs maintenance keeps
visible. Each one makes the active scope visible **before** edit or export and
keeps pending suggestions, compare history, and the publish boundary inspectable
after the user leaves the surface.

They validate against
[`schemas/docs/release-docs-maintenance.schema.json`](../../../../schemas/docs/release-docs-maintenance.schema.json),
and the canonical contract review packet lives at
[`artifacts/docs/m5/release-docs-proof/review_packet.json`](../../../../artifacts/docs/m5/release-docs-proof/review_packet.json).
All files here are regenerated by the headless inspector:

```sh
cargo run -p aureline-docs --bin aureline_docs_release_docs_surface -- surface <surface_id>
```

## readme_installed_stable.json

The project **README** whose evidence scope is `installed_stable` — it matches
the running build (`exact_build_match` / `authoritative_live`). The boundary is
`local_only`, the compare history is `working_vs_installed`, and the surface is
wired to the help browser and About panel. Demonstrates that only prose that
actually matches the installed build may be labeled installed stable.

## changelog_beta.json

The **changelog** for `release:beta-2` on the `beta` channel. Its evidence scope
is `shared_prerelease` and the boundary is `publish_handoff_scoped`, so the
branch/release/channel scope and publish-boundary notes are shown before export.
The compare history is `channel_vs_channel` (beta versus stable) and it
integrates the release center and support export. Demonstrates that a beta
changelog never masquerades as the installed stable changelog.

## onboarding_shared_review.json

An **onboarding note** shared for review (`shared_review` / `review_handoff_scoped`)
on a beta onboarding branch. The compare history is `branch_vs_release` and the
surface integrates the help browser. Demonstrates that review-scoped work carries
its branch/channel scope and stays inside review.

## release_notes_blocked.json

A **release notes** draft on a `private_branch` with no release/channel scope.
The boundary is `blocked_unscoped`: there is no apply/export action, and the
publish-boundary notes explain that a scope must be added to enable a handoff.
Demonstrates that a release-facing doc cannot publish on unstated assumptions.

## readme_next_draft.json

A **README** draft for the `next` channel whose evidence scope is `local_draft`.
The boundary is `local_only`, but because the draft is not installed stable it
still names the branch and channel it targets, and the compare history is
`working_vs_installed`. Demonstrates that a note drafted for the next channel is
explicitly labeled and cannot be mistaken for the currently installed stable
README.
