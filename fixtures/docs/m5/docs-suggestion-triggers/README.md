# Docs Suggestion Panel Fixtures

These fixtures are docs-suggestion-panel packet materialization inputs (`input`)
paired with the `promotion_state` and `expected_finding_kinds` the validator must
produce. They are regenerated by:

```sh
cargo run -q -p aureline-docs --bin aureline_docs_suggestion_panel -- fixture <case_name>
```

The canonical clean-Stable panel lives in
[`artifacts/docs/m5/docs-suggestion-proof/support_export.json`](../../../../artifacts/docs/m5/docs-suggestion-proof/support_export.json);
these fixtures exercise the narrowing and blocking paths around it.

## mirror_offline_narrows.json

The docs mirror is offline, so the imported broken-link suggestion is served from
the last snapshot. The narrowing degradation keeps every suggestion visible and
attributable, so the panel narrows to `narrowed_below_stable` instead of hiding
the suggestions — the downgrade narrows the claim, it does not hide the work.

## prose_only_card_blocks_stable.json

A README suggestion is a prose-only "recommended edit" card with no diff.
Diff-first proposals are mandatory, so the validator blocks promotion with
`proposal_not_diff_based` — docs maintenance may not bypass the shared review/diff
model just because the target is prose.

## unverified_apply_blocks_stable.json

An imported, mirror-served broken-link suggestion offers a one-click apply.
Action-parity apply gating is mandatory, so the validator blocks promotion with
`unverified_apply_offered` — an unverified evidence source may surface a preview
but never a one-click apply.
