# Ranking-explainability and ranking-partiality fixtures

- `packet.json`: canonical explainer. Each of the five claimed surfaces (palette,
  sidebar, docs results, graph-backed results, saved-query reopen) carries
  user-visible `Why this result?` explain sheets that reuse the canonical
  `RankingReason` object verbatim, plus omitted-candidate rows that make
  withheld-latency and policy-hidden candidates inspectable. The packet jointly
  realizes the six fact labels (exact, context_promoted, semantic, partial_index,
  withheld_latency, policy_hidden) and the six explainer states (promoted,
  suppressed, tied, partial_index, withheld_latency, policy_hidden). Sessions are
  referenced hash-only, raw numeric score weights are excluded, and the export
  posture is metadata-only.
- `partial_index_stale.json`: degraded explainer where the live index is
  partial/stale, so semantic coverage narrows (stronger partiality caveats) and
  the palette and docs surfaces withhold strictly more candidates for latency or
  pending indexing, while result identity, the explainer vocabulary, and the
  reused explanation object are preserved unchanged. Saved-query reopen reads
  local material and stays unchanged.

Each fixture is regenerated by
`crates/aureline-search/examples/dump_ranking_explainability_packet.rs` and
replayed against the seeded explainer by the inline tests in
`crates/aureline-search/src/ranking_explainability/tests.rs`.

Regenerate:

```bash
cargo run -p aureline-search --example dump_ranking_explainability_packet -- canonical \
  > fixtures/search/m5/ranking-partiality/packet.json
cargo run -p aureline-search --example dump_ranking_explainability_packet -- partial_index_stale \
  > fixtures/search/m5/ranking-partiality/partial_index_stale.json
```
