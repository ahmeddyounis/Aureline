# Stash & recovery fixtures

These fixtures are valid, export-safe `git_stash_recovery_packet` packets that
each narrow the canonical sheets packet to a single verb, exercising a decision
path the canonical packet does not. Every sheet's decision re-derives from its
gate states, so the stored outcome can be verified against the same gates every
surface reads.

All three are generated by the conformance dump:

```bash
cargo run -p aureline-git --example dump_stash_recovery -- pop-conflict
cargo run -p aureline-git --example dump_stash_recovery -- reflog-only
cargo run -p aureline-git --example dump_stash_recovery -- provider-outage
```

## stash_pop_conflict_blocked.json

A stash-pop whose apply would hit an unresolved conflict. The decision is
`blocked` with reason `blocked_unresolved_conflict`, yet the sheet still names its
exact stash entry and keeps `local_truth_available_offline` true — a blocked verb
never hides the local inspect/restore truth, and `restore_checkpoint` stays in the
local actions.

## reflog_restore_only_caveats.json

A reflog-restore whose anchor is expiring soon and whose only recovery is a
reflog-only fallback (no full checkpoint). Both gates downgrade rather than block,
so the decision is `downgraded`, and the restore caveats (`anchor_expiring_soon`,
`reflog_only_no_full_checkpoint`, `reflog_entry_may_expire`) are preserved — a
reflog-only restore never pretends to be a durable checkpoint.

## stash_apply_provider_outage_local_only.json

A stash-apply whose provider overlay is unavailable. The provider gate downgrades
rather than blocks, so the decision is `downgraded` and local truth stays
available offline — a provider outage can never block local preview, continue,
abort, stash inspection, or checkpoint restore.
